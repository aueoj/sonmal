# 손말 UX 분석: 수어를 배우고, 수어 사용인과 대화한다는 느낌

범위: 연습 화면 전체(카메라, 단어 칩, 안내 카드, 말하기, 표 보기)
화면 크기: 1440×900, 390×844 / 모의 손 입력 / 2026-11-02 / 판 202611021248 기준
방법: ux-ui-audit 측정 스크립트(core, heuristics, perception, focus) + 화면 캡처 + 문구와 데이터 읽기
기준: 접근성은 WCAG 2.2, 사용성은 Nielsen 10가지 원칙에 근거한 판단. 심각도 구분은 판단이지 표준이 아니다.

## 요약

치명 1, 중대 6, 접근성 4, 참고 1

질문에 대한 답부터. 지금 손말은 **"수어 그림을 보고 따라 해 보는 도구"**다.
"배운다"는 느낌이 약한 이유는 해냈다는 판정이 수어와 무관하고(01), 배운 것이 남지 않기 때문이다(04).
"대화한다"는 느낌이 없는 이유는 문장이 한국어 순서의 지문자로 풀리고(02), 상대의 수어를 읽어 주는 방향이 없기 때문이다(03, 07).
반대로 기반은 좋다. 낱말 37개가 모두 국립국어원 사전 항목을 따르고, 판정에 쓸 데이터(`check`)와 표정 데이터(`비수지`)가 이미 들어 있는데 화면이 쓰지 않을 뿐이다.

## 발견

### 01, 치명, 낱말 연습
**낱말은 어떤 동작이든 손을 흔들면 '해냈다'가 된다.**
사용자는 틀리게 해도 칭찬을 받고, 그것이 맞는 수어라고 기억한다. 학습 도구에서 가장 비싼 실패다.
```
js/app.js:302  const ready = held >= need && moved >= WORD_MOVE;
               // 손이 그림 한 바퀴 시간 동안 보이고, 손 길이의 0.34배만 움직이면 통과
js/app.js:196  state.tracker.setMockPose(getPose('ㅂ'));   // 모든 낱말을 같은 손모양으로 흉내 내도 통과한다
js/wordBank.js  39개 낱말 모두 단계별 check { hands, fingers, zone } 를 갖고 있으나 app.js 는 읽지 않는다
```
FIX: 단계마다 `check` 를 판정에 쓴다. 손 수, 펴진 손가락, 손 위치(얼굴, 턱, 가슴, 배)를 각 장에서 확인하고, 다르면 지문자처럼 "검지만 펴세요", "턱 높이로 올리세요"라고 짚는다. 이미 지문자 판정기(`scorePose`)와 손 위치 좌표가 있어 새 모델 없이 된다.

### 02, 중대, 문장 말하기
**말한 문장을 한국어 어순 그대로 낱말과 지문자로 풀어, 수어 문장이 되지 않는다.**
흔한 질문 하나를 손으로 하는 데 지문자 13동작이 든다. 대화 속도로는 쓸 수 없고, 수어 사용인은 이렇게 말하지 않는다.
```
이름이 뭐예요        낱말 수어 0/2 어절, 지문자 13동작
이거 참 어렵네요      낱말 수어 1/3 어절, 지문자 12동작
저는 학생입니다       낱말 수어 1/2 어절, 지문자 13동작
다시 천천히 말해 주세요  낱말 수어 2/4 어절, 지문자 11동작
화장실 어디예요       낱말 수어 2/2 어절, 지문자 0동작
```
FIX: (1) 조사와 어미를 떼고 기본형으로 찾는다(어렵네요 → 어렵다, 뭐예요 → 무엇, 이름이 → 이름). (2) 수어에서 보통 생략되는 '은/는/이/가/을/를'은 지문자로 풀지 않는다. (3) 사전 용례를 바탕으로 자주 쓰는 문장 몇 개는 수어 어순으로 미리 만들어 둔다. (4) 그 전까지는 화면에 "한국어 순서로 낱말을 이어 본 것"이라고 밝힌다.

### 03, 중대, 수어 → 말
**손말은 지금 보여 준 자모 하나와만 견준다. 상대가 한 수어를 읽어 주지 못한다.**
'대화'의 절반인 상대 쪽 방향이 없다. 처음 주신 기획의 "수어를 하면 음성으로 알려 준다"도 지금은 "정답을 맞히면 정답을 읽는다"에 가깝다.
```
js/app.js:328  const base0 = ...pose   // 지금 칸의 자모 하나
js/app.js:329  scorePose(feat, base0, ...)  // 40개 중 무엇인지 찾지 않고, 정답과만 견준다
dev/selftest.mjs  40개 손모양 중 32개는 서로 가려진다(자기인식 32/40)
```
FIX: '읽기 모드'를 따로 둔다. 지문자는 40개 전체와 견줘 가장 가까운 것을 고르고, 모인 자모를 글자로 합쳐 읽는다(이미 있는 `composeFromJamo`). 낱말은 01의 `check` 로 37개 중 후보를 좁히는 데서 시작한다.

### 04, 중대, 학습 흐름
**배운 것, 틀린 것, 다음에 할 것이 남지 않는다.**
끝나면 "좋아요. 다시 해 볼까요"를 영원히 되풀이한다. 매번 처음이라 성장하는 느낌이 없다.
```
js/*.js 13개 파일에서 저장(localStorage) 사용 0회
finish() → 1.4초 뒤 같은 말을 처음부터 다시
```
FIX: 이 기기에만 남는 기록(익힌 낱말, 자주 틀린 손모양)과 '오늘의 낱말 5개'. 익힌 뒤에는 그림을 숨기고 말만 보여 주는 떠올리기 연습(보고 따라 하기 → 안 보고 하기)을 붙인다.

### 05, 중대, 안내 카드
**표정(비수지)과 사전 원문을 데이터에 갖고 있으면서 보여 주지 않는다.**
수어는 표정이 문법이다. 묻는 말 6개는 모두 '묻는 표정'이 있어야 질문이 되는데, 사용자는 그 사실을 볼 수 없다.
```
js/wordBank.js  비수지 17/39개   (무엇=묻는 표정, 왜=의문스러운 표정, 슬퍼요=슬픈 표정 …)
                원문 39/39개     (국립국어원 수형 설명)
js/app.js       '비수지' 0회, '원문' 0회 참조
```
FIX: 카드에 한 줄 "표정: 묻는 표정"을 더하고, "사전 영상" 링크(국립국어원 항목, 새 탭)를 단다. 그림은 멈춘 장면이라 움직임을 다 담지 못하는데, 사전 영상이 그 빈자리를 메운다. 데이터가 이미 있어 가장 싸게 '배운다'는 신뢰를 올리는 고침이다.

### 06, 중대, 단어 고르기
**38개 칩을 한 줄로 늘어놓아, 무엇부터 배울지 정할 수 없다.**
```
nav#chips  선택지 38개, Hick 지수 5.29 (보통 화면 3.2~4.0)
첫 화면 상호작용 요소 25개 (1440 폭)
```
FIX: 갈래 대신 상황으로 묶는다. "처음 만났을 때(안녕하세요, 나, 이름, 반갑다)", "도움이 필요할 때(도와주세요, 화장실, 어디)", "대화가 막힐 때(다시, 천천히, 이해했어요)". 한 묶음 5~7개. 대화 장면이 먼저 보이면 '대화를 배운다'는 느낌이 바로 생긴다.

### 07, 중대, 대화 장면
**수어 사용인과 마주 앉아 쓰는 화면이 없다.**
지금 화면은 혼자 거울 앞에서 연습하는 구조다. 대화 상대가 볼 자리도, 상대 말을 받을 자리도 없다. (측정이 아닌 판단: Nielsen "현실 세계와 맞물림")
FIX: '대화 모드'. 화면을 위아래로 나눠 위쪽(상대 쪽)에는 내가 말한 문장을 큰 글자로, 아래쪽(내 쪽)에는 그 문장의 수어 그림을 둔다. 상대가 수어를 하면 03의 읽기 결과를 아래에 띄운다. "대화가 막힐 때" 칩(다시, 천천히, 저는 수어를 배우는 중이에요)을 항상 닿는 곳에 둔다.

### 08, 접근성, 입력칸
**문장 입력칸에 이름이 없다.** WCAG 4.1.2, 3.3.2
```
input#typed  accessibleName "" , placeholder 만 있음: "또는 문장을 입력하고 엔터"
```
FIX: `aria-label="말할 문장"`.

### 09, 접근성, 입력칸
**입력칸에 키보드 초점 표시가 없다.** WCAG 2.4.7
```
Tab 순서 2번째 input#typed  outline: none  (감싼 알약 테두리만 rgba(255,255,255,.4) 로 바뀜)
다른 버튼들  outline 2px solid rgb(94,106,210), offset 2px  → 통과
```
FIX: `.say:focus-within` 에 2px 선명한 테두리.

### 10, 접근성, 안내 카드
**밝은 영상 위에서는 동작 설명 글씨 대비가 부족하다.** WCAG 1.4.3
```
p#guide-step  rgba(255,255,255,.82) / 배경 rgb(106,106,109)  →  4.25:1 (기준 4.5:1)
측정 조건: 영상 대신 밝은 바탕. 어두운 영상 위에서는 더 높다.
```
FIX: 카드 바탕 불투명도를 .62에서 .72로, 또는 글씨를 #fff 로.

### 11, 접근성, 입력칸
**입력칸 높이가 23px로 최소 크기에 1px 모자란다.** WCAG 2.5.8 (24×24)
```
input#typed  419×23 (1440 폭), 133×23 (390 폭)
```
FIX: 높이 32px.

### 12, 참고, 해결됨
'이거'라고 말하면 칸과 안내에 '여기'가 나오던 것은 오늘 고쳤다. 이제 칸과 읽어 주는 말은 사용자가 한 말 그대로이고, 수어 표제어는 카드에 작게 알린다.

## 잘 되는 것

- **출처가 분명하다.** 화면의 낱말 37개 모두 국립국어원 사전 항목 번호와 원문을 갖고, 점검이 출처 없는 낱말을 막는다.
- **조작이 적다.** 390 폭 첫 화면에 보이는 상호작용 요소 11개, Hick 지수 3.58(보통 범위).
- **반응이 빠르다.** 페이지를 연 뒤 카메라 켜짐까지 1.6초, 50ms 넘는 긴 작업 0건.
- **누르기 쉽다.** 누를 수 있는 요소 45개 중 44개가 24px 이상(나머지 하나가 11번 입력칸), 그림 39개 모두 대체 글이 있다. 건너뛰기 링크가 있다.
- **초점 표시**는 버튼 전부 2px 실선, 2px 간격.

## 어디서 시작할까 (효과 ÷ 품)

1. **08, 09, 11** 접근성 세 줄. 몇 분이면 끝난다.
2. **05** 표정 한 줄과 사전 영상 링크. 데이터가 이미 있다. '배운다'는 신뢰가 바로 오른다.
3. **06** 상황별 묶음. 칩 데이터만 다시 나누면 된다.
4. **02 (1)(2)** 조사, 어미 떼기. 작은 함수 하나로 지문자 동작 수가 크게 준다.
5. **01** 낱말 단계 판정. 데이터는 있고 판정 연결이 일이다. 학습 도구로서 가장 중요하다.
6. **04** 기록과 떠올리기 연습.
7. **03 → 07** 읽기 모드, 그다음 대화 모드. 가장 크지만 '대화한다'는 느낌의 본체다.
