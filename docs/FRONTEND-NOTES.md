# 프론트엔드 점검에서 나온 것

이 앱을 셀프 점검하며 실제로 잡은 결함과, 그걸 잡아낸 방법을 적는다.
(프론트엔드 스킬 설치본에 `LEARNINGS.md`가 없어 프로젝트 쪽에 남긴다.)

## 잡은 결함

| 결함 | 증상 | 무엇이 잡았나 |
|---|---|---|
| 캔버스 이중 반전 | 영상과 캔버스에 둘 다 `scaleX(-1)`, JS도 좌표를 반전 → 랜드마크가 영상과 어긋남 | 계산된 스타일 비교 |
| `object-fit: cover` 미보정 | 정규화 좌표를 요소 크기에 그대로 곱해 잘린 만큼 어긋남 | 코칭 중 화면 캡처 |
| 확정 애니메이션 소실 | `data-lock` 설정 직후 `innerHTML` 재생성 → 유일한 모션이 영영 안 보임 | DOM에서 `[data-lock]` 개수 세기 |
| 문턱 근처 떨림 | 점수가 문턱을 오르내려 버티기 시간이 매 프레임 초기화. 맞는 자세인데 확정 안 됨 | 루프 끝까지 돌리기 |
| 이동 감지 창이 프레임 수 기준 | 60fps에서 230ms, 느린 환경에서 840ms — 같은 코드가 다르게 동작 | 프레임률을 바꿔 계산 |
| 모의 입력에 움직임 없음 | 쌍자음 경로가 한 번도 시험되지 않음 | 쌍자음 포함 문장으로 루프 |
| 모순된 피드백 | 미터는 "맞습니다 77%"인데 교정 힌트가 같이 뜸 | 화면 캡처 |
| `flex: 1` + `min-width: auto` | 시퀀스 레일이 내용보다 작아지길 거부 | 계산된 `min-width` 확인 |
| `color-scheme` 미선언 | OS가 다크일 때 input·dialog 크롬이 어두워짐 | 다크 설정으로 재방문 |
| 구두점이 지문자로 | `반갑습니다!`의 `!`가 시퀀스에 들어가 700ms 낭비 | 폼 제출 후 자모 확인 |
| 모달 이름 없음 | `aria-labelledby` 없음, 포커스가 본문 링크로 감 | 모달 접근성 확인 |

## 배운 것

**순위 시험은 문턱 시험이 아니다.** 자기인식 28/28은 "자기 자세에서 자기가 1등"만 본다.
확정은 절대 점수가 문턱을 넘어야 일어나므로 따로 쟀어야 했다. 완벽한 자세의 자기 점수가
전부 0.82 이상인 것을 확인하고 나서야 문턱 문제가 아님을 알 수 있었다.

**테스트가 틀렸을 수 있다.** `안녕하세요`가 멈춘다고 나왔지만 실제로는 멈춤 감지가
'시작 후 6초'라는 고정 기준이어서 정상 진행 중에 발동한 것이었다. '진행이 멈춘 채
얼마나 있었나'로 바꾸니 통과했다. 앱을 고치기 전에 측정 도구를 의심한다.

**모의 입력이 못 만드는 것은 시험되지 않는다.** 모의 손이 정적이라 쌍자음 경로가
통째로 미검증이었다. 모의 입력은 실제 동작의 모든 축을 흉내 내야 한다.

## 점검 도구

```bash
node dev/selftest.mjs             # 자모가 서로 구별되는가
node dev/audit.mjs                # DOM·접근성·넘침·콘솔
node dev/loop-audit.mjs '안녕하세요'  # 말 → 손모양 → 인식 → 재합성 → 음성, 끝까지
node dev/visual.mjs               # 코칭 중 화면, 다크 OS, 모션 감소
```

`loop-audit`은 재합성 결과가 입력 문장과 같을 때만 0으로 끝난다.
